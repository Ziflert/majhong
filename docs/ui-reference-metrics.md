# Эталон интерфейса: метрики из макетов

Источник истины — макеты `examples/Эскизы UI Маджонг.html` (кадры 1–5) и их растровые
рендеры `examples/task/1 · Игровой стол (ПК).png` … `5 · Игровой стол (мобильный).png`.
Кадр 1 — игровой стол, 2 — меню паузы, 3 — главное меню, 4 — настройки, 5 — мобильный стол.

Разобранный текст кадров лежит рядом (одна строка CSS на элемент):
`Logs/frame1.txt` … `Logs/frame5.txt` (это те же `examples/extracted/frameN_body.html`,
развёрнутые из `\n` и `\u002F`; их можно читать как обычный HTML).

## Как читать числа

Все числа ниже — **дизайн-пиксели листа 1280×720**. Макет масштабируется по высоте кадра,
поэтому в коде это `units = 2·halfHeight / 720`. Настройка «Масштаб интерфейса» умножает
`units` так же, как сейчас (`UiStyle.Scale`); размеры текста ещё и `UiStyle.TextScale`.

Правила, которые важнее конкретных чисел:

- **Ни один элемент не перекрывает другой** ни при каком разрешении 16:9 / 16:10 и ни на
  одном языке. Текст всегда вписывается в свою плашку (измерить и уменьшить кегль), плашка
  под текст не растягивается, если это ломает сетку.
- Позиция группы задаётся якорем (`left/right/top/bottom` + отступ), а не шириной соседа.
- Цвета — только `UiStyle.Of(UiRole…)`, поверхности — `UiSkin`, строки — `Loc`. Числа,
  зависящие от размера экрана, — только тут, в константах с комментарием.

## Что считается браком

- Две надписи или две плашки в одном месте экрана.
- Текст, вылезший за плашку или обрезанный её краем.
- Плашка/панель, выехавшая за кадр или подрезанная краем.
- Рука игрока, накрытая кнопками, подсказкой или столом.
- Стол, заходящий под верхнюю полосу или под руку.
- Плашки мест, пересекающие стол.
- Видимый 3D-стол за главным меню.
