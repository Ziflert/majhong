## Затупы

**З-1. Проект не открывался в редакторе Unity.** 🟡
Установлено: Unity Hub 3.22.5 (`D:\Software\Unity\Hub`) и редактор Unity 6.0 LTS 6000.0.85f1
(`D:\Software\Unity\6000.0.85f1\Editor\Unity.exe`), Hub знает эту папку как install path.
`ProjectSettings/ProjectVersion.txt` создан, при первом batchmode-запуске Unity сгенерировала
дефолтные `ProjectSettings` с legacy Input Manager (`activeInputHandler: 0`) — значит `UnityEngine.Input`
в прототипе рабочий.
Осталось: лицензия. Без аккаунта Unity редактор не запускается
(`No valid Unity Editor license found`, exit 198). Нужно войти в Hub (Personal бесплатен) и активировать
лицензию, после чего импортировать проект и проверить Play.
Риски на первого запуска: шрифт `TextMesh`, `FindObjectOfType` (в Unity 6 помечен obsolete),
позиционирование объектов, `Camera.main`. Это блокер для пунктов 4.7–4.15.

**З-2. Матрица исключений фанов неполная.** 🟡
Часть пар «не совмещается» взята из таблицы 3.8.1 и приложения 1 перевода, часть — из официальных
MCR-описаний. Полной официальной таблицы импликаций в руках нет.
Риск: редкие руки посчитаются на 1–8 очков больше или меньше.
Что делать: прогнать 20–30 эталонных рук через независимый MCR-калькулятор и сверить разбивку.

**З-3. Нет эталонных чисел для проверки подсчёта.** 🟡
Самопроверки проверяют то, что я сам заложил: структуру, отсутствие лишних фанов, суммы. Внешнего
источника истины по очкам нет.
Что делать: завести `docs/scoring-golden.md` с 20–30 руками и ожидаемыми разбивками из калькулятора,
превратить их в тесты.

**З-4. Русский перевод правил местами ошибается.** 🟡
Уже поймано: Чистые терминальные чоу — 64, а не 48. Перевод приложения 1 местами расходится с
таблицей 3.8.1.
Что делать: всё спорное сверять по официальному изданию (китайский/английский оригинал), фиксировать
в `docs/rules-status.md`.

**З-5. Раздача и геометрия стены упрощены.** 🟡
Кости раздаются последовательными группами по 4 от точки разрыва; «верх первой и третьей стопки» не
воспроизводится. Разрыв — смещение в костях, а не в стопках.
Влияние: на распределение костей — нулевое, на визуализацию стены — есть.
Что делать: решать при работе над анимацией стены.

**З-6. Человек не может объявлять Чи/Панг/Конг.** 🟡
Движок это умеет и отдаёт в `GetLegalActions`, но в 3D-прототипе нет UI выбора.
Что делать: пункт 4.7 — панель доступных действий с подсказками из `LegalAction.Description`.

**З-7. Бот уровня 1 играет «в скорость», а не в очки.** 🟡
Не считает ценность руки, не избегает опасных сносов, не следит за счётом матча. Для прототипа
достаточно, для игры — нет.
Что делать: пункты 3.3–3.4 после того, как появится UI.

**З-8. Нет слоя нарушений и штрафов.** ⬜
3.9.1.2.3, 3.11 (ошибочный Ху, пустое требование, касание кости, поздний панг) не моделируются.
Для одиночной игры против ботов почти не нужно; для сетевой/турнирной — нужно.
Что делать: отдельный модуль `Rules/Penalties.cs` + поле штрафных очков в сессии.

**З-9. Локальный .NET SDK вне репозитория.** ℹ️
Лежит в `D:/Temprary/dotnet-sdk`. Если папку удалить, `dotnet run --project Tools/RulesCheck`
перестанет работать; на саму игру это не влияет.
Что делать: либо поставить SDK системно, либо оставить и помнить.

2. **UI выбора действия** (4.7) — человек должен уметь Чи/Панг/Конг/Пас, а не только снос и Ху.
3. **Эталонные руки для подсчёта** (З-2, З-3) — закрепить очки внешним источником, иначе ошибки
   подсчёта всплывут уже на игроках.
