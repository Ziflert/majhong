# Unity-слой (3D-прототип)

Слой представления отделён от логики: `Assets/Scripts/Mahjong` не знает про Unity,
`Assets/Scripts/MahjongView` — это MonoBehaviour-обёртки.

| Файл | Назначение |
|---|---|
| `MahjongView/TileObject.cs` | 3D-тайл из примитивов: куб-тело + Quad с атласом лица (fallback — `TextMesh`) |
| `MahjongView/TileLabel.cs` | Короткая подпись и цвета для каждого типа кости |
| `MahjongView/ActionBar.cs` | Панель действий: кнопки из `ActionPrompt`, подсказка, попадание лучом |
| `MahjongView/ActionButton.cs` | Одна кнопка панели: куб-плитка + подпись, коллайдер на корне |
| `MahjongView/MahjongGame.cs` | Сборка сцены, сессия, ходы человека и ботов, ввод мышью, отсчёт времени, журнал ходов, сохранение и просмотр партии, открытие руки |
| `MahjongView/TableLayout.cs` | Где что стоит: квадрат стен, ряд руки, ряд комбинаций, сбросы, цветы, таблички мест; размер сукна выведен из длины стены |
| `MahjongView/DiceTray.cs` | Две кости в середине стола: бросок, очки, остановка (3.5.7.5) |
| `Rules/WallGeometry.cs` | Место кости в стене: сторона, стопка, ярус; кольцо из 144 позиций и место разрыва (без Unity) |
| `Controls/HandOpening.cs` | Такты открытия руки: два броска, разрыв, раздача; `TimeUntilDeal`, `Skip`, пересчёт скорости в темп (без Unity) |
| `Replay/SessionLog.cs` | Файл сохранённой партии: шапка, шапки рук, строки ходов; чтение с указанием битой строки (без Unity) |
| `Replay/ReplayCursor.cs` | Позиция внутри партии для просмотра: ход вперёд/назад, соседняя рука, описание хода (без Unity) |
| `Replay/SessionRestore.cs` | Продолжение партии из файла: счёт из переигранных рук, часы сессии, недоигранная рука (без Unity) |
| `Controls/PlayClock.cs` | Окна времени руки: 20 секунд на расстановку, 10 на снос, 3 на заявку (без Unity) |
| `Controls/ClockExpiry.cs` | Что происходит по истечении окна: молчание = Пас, просроченный ход доигрывается |
| `Editor/PrototypeCapture.cs` | Прогон прототипа из командной строки: Play, скриншоты, отчёт, выход |
| `Editor/ActionBarPreview.cs` | Скриншот панели действий на заранее заданном наборе кнопок |

## Как запустить

Установлено: Unity Hub 3.22.5 и редактор Unity 6.0 LTS 6000.0.85f1 (`D:\Software\Unity`),
версия проекта закреплена в `ProjectSettings/ProjectVersion.txt`.

1. Открыть проект:
   `"D:\Software\Unity\6000.0.85f1\Editor\Unity.exe" -projectPath "D:\Temprary\game"`
2. Нажать Play в любой сцене (можно в пустой Untitled): `MahjongGame` добавляет себя сам через
   `RuntimeInitializeOnLoadMethod`, генерирует камеру, свет, стол и тайлы кодом.
3. `.unity`-файлов в репозитории нет намеренно — сцена целиком строится кодом.

Альтернатива: положить `MahjongGame` на пустой GameObject вручную и задать в инспекторе
`humanSeat`, `botDelay`, `randomSeed`.

## Что уже играется

- сессия из 16 рук (4 раунда × 4 руки), смена разыгрывающего;
- один человек (место 0) против трёх эвристических ботов;
- рука игрока выкладывается в ряд слева направо по возрастанию масти и ранга;
- клик по кости — снос, клавиша `H` — объявить Ху;
- Чи, Панг, Конг, Ху и Пас — кнопками панели действий: клик мышью или клавиши `1`..`9`;
  порядок кнопок — приоритет заявок (сначала Ху, потом конги, панги, чоу, пас), подсказка под
  кнопками — текст `LegalAction.Description` от движка;
- таймер ботов пасует за них, но за человека не пасует: пока у него есть настоящая заявка, окно открыто;
- сбросы лежат блоками по четвертям стола, кости соперников — рубашкой вверх;
- все 144 кости стоят на столе: стена — четыре стены по 18 стопок в две кости, разданная кость
  уезжает из своего места в стене, а не появляется из воздуха;
- в начале руки бросаются два кубика, на посчитанной стопке отмечается разрыв (короткая жёлтая планка),
  и лицо кости открывается только в руке;
- HUD привязан к камере: номер руки, раунд, место, остаток стены, счёт;
- после руки — экран результата с расчётом выплат, затем следующая рука;
- партия пишется в файл сама (после каждой руки, по `F5`, при выходе) и листается клавишей `V`;
- меню на `Esc`: язык, сила и темп ботов меняются на месте, рука на это время стоит.

## Отсчёт времени

Правила дают три окна: 20 секунд на расстановку костей до первого сноса (3.5.7.6), 10 секунд на снос
(3.6.4) и 3 секунды на объявление панг/конга (3.6.7). Считает их `PlayClock` — обычный класс без
Unity: слой представления подаёт ему `Time.deltaTime`, а тесты — любое нужное время, поэтому «окно
закрывается через три секунды» проверяется без ожидания.

- окно открывается на каждое решение человека, ключ решения — номер действия движка (`stateVersion`),
  поэтому отсчёт не перезапускается каждый кадр;
- окно не открывается там, где решать нечего: если человек может только пасовать, движок и сам
  закроет окно заявок;
- по истечении окна заявки человек «молчит», и это Пас (`ClockExpiry`); объявить Ху за молчащего
  игрока нельзя — ложный Ху это штраф 3.11.6.6;
- по истечении окна сноса кость сносится за человека — тем же ботом, что играет за его место;
- HUD показывает последнюю строку `Arrange your tiles: N s` / `Time to discard: N s` /
  `Time to claim: N s`; строка перерисовывается только при смене текста, раз в секунду;
- первый снос человека в руке получает 20 секунд (формально правило отводит их до первого сноса
  разыгрывающего), дальше — по 10.

`MahjongGame` отдаёт наружу `HandClock`, `Phase`, `CurrentSeat`, `DiscardTileCount` и
`OpponentConcealedTileCount`, а также `AdvanceClock(seconds)` — им тест и прогон со скриншотами
перескакивают ожидание вместо `sleep`.

3 — если на столе нет тайлов или статус-строки. Печатает число тайлов и текст HUD в лог.

3 — если стол не поднялся; в лог по каждому кадру печатается, что на нём видно (страница
справочника, число костей свободного стола, число ходов середины руки, число строк меню и строка
под курсором, позиция просмотра, шаг открытия и очки на кубиках).
Шаг `table-midgame` проматывает окна человека часами — без него за столом без игрока не набирается
ни одного хода и кадр просмотра вышел бы пустым.

## Меню и настройки стола

`Esc` открывает меню и ставит руку на паузу: часы руки и боты стоят, стрелка часов сессии тоже,
а когда меню закрывается, окно решения открывается заново с полным временем. Меню живёт в двух
слоях: `Controls/GameMenu.cs` — что оно делает (восемь строк, курсор с переносом, шаг настройки,
команда строки), `MahjongView/MenuPanel.cs` — как оно выглядит (плашки, подписи, подсветка,
попадание лучом). Размер панели считается от `fieldOfView` и `aspect` камеры — как у справочника.

Строки: язык, темп ботов (×0.25 / ×0.5 / ×1 / ×2 / ×4), сила ботов (быстрый / осторожный /
стратег), сохранить, продолжить сохранённую, просмотр партии, правила, вернуться за стол.
Клавиши: `↑`/`↓` — строка, `←`/`→` — значение, `Enter` — выбрать, `Esc` — за стол; клик мышью
по строке — это выбор строки.

Настройки живут в `Controls/GameSettings.cs`, и у каждого значения одно место разбора и одно
умолчание: строка меню, тест и прогон из CLI не могут разойтись в том, что значит «уровень 2»:

| Переменная | Что делает |
|---|---|
| `MAHJONG_LANG` | язык интерфейса (`ru`/`en`) |
| `MAHJONG_BOT_LEVEL` | сила ботов: `1`..`3` или имя (`fast`, `cautious`, `strategic`) |
| `MAHJONG_BOT_SPEED` | темп ботов множителем (`0.5`, `4`); к ближайшей ступени лестницы |

Числа читаются в инвариантной культуре: под русской локалью `0.5` не должно молча стать
«непонятным значением» — на этом уже спотыкались `MAHJONG_SESSION_MINUTES`.
Смена силы ботов пересобирает их на ходу (тем же сидом), темпа — просто делит задержку
между ходами: `botDelay / Speed`.

## Стена, кубики и открытие руки

Стена — не украшение стола, а источник состояния: `Rules/WallGeometry.cs` описывает её так, как
её строят правила (3.5.7.4). Вся стена — одно кольцо из 144 позиций; `WallSlot(side, stack, level)` —
сторона (по местам), стопка (от правого конца этой стороны) и ярус (1 — верхняя кость стопки,
её берут первой). Кольцо идёт по часовой стрелке, если смотреть сверху: игрок берёт свою стену
от правого конца к левому, потом стену слева, поэтому `RingStart` считает стороны назад: 0, 3, 2, 1.

`Wall` хранит кости в порядке кольца (`TilesInRingOrder`), поэтому разложить стол можно из самой
стены: `SlotOf(tile)` говорит, где кость стояла, `IsStanding(tile)` — стоит ли она ещё.
Разрыв — `Break(thrower, stacks)`: `stacks` = сумма обоих бросков (`GameState.BreakStacks`),
отсчитывается от правого конца стены второго бросавшего. Своя стена держит 18 стопок, а сумма
двух бросков — от 4 до 24, поэтому счёт за концом стены переходит в следующую: тест, который ждал
разрыв всегда в стене бросавшего, падал на 16 % раздач.

**Такты открытия.** Открытие руки — это время, а не анимация, поэтому оно живёт в
`Controls/HandOpening.cs`, без Unity и с headless-проверкой:

| Такт | Длина | Что видно |
|---|---|---|
| `FirstRoll` | 0.9 с | первый бросок: кто бросает второй раз (3.5.7.5) |
| `SecondRoll` | 0.9 с | второй бросок: сумма даёт разрыв |
| `Break` | 0.6 с | разрыв: планка у посчитанной стопки |
| `Deal` | 1.1 с | кости уезжают из стены в руки |

`TimeUntilDeal` — сколько стол ещё ждёт до первой взятой кости; `Progress` (0..1) и
`ElapsedInStep` читает анимация костей; `Advance` возвращает true только на смене такта, чтобы
пересборка стола случилась один раз, а не 60 в секунду; `Skip` перескакивает открытие без ожидания.
Пока открытие идёт, стол не принимает клики: кости руки ещё стоят в стене.

| Переменная | Что делает |
|---|---|
| `MAHJONG_OPENING_SPEED` | скорость открытия: `0` — без показа (сразу собранная рука), `2` — вдвое быстрее, `0.5` — вдвое медленнее; по умолчанию 1. `PrototypeCapture` выставляет `0` сам |

`Pace` в `HandOpening` — это длина такта, а не скорость, поэтому `HandOpening.PaceFromSpeed`
один раз переводит одно в другое (раньше `MAHJONG_OPENING_SPEED=2` замедлял открытие вдвое).

**Раздача из стены.** `MahjongGame.PlaceWall` ставит все 144 кости в их места до раздачи, и
разданная кость — это та же самая вьюха, которая стояла в стене: она уезжает из своего места в руку.
Задержка старта считается по расстоянию до разрыва: 53 кости идут по кольцу в руку, замены цветов
— с другого конца (`ReplacementDelay = 0.85` с, чтобы замены не летели одновременно с раздачей).
Что никто не взял — остаётся стоять с дырками до конца руки; после руки стол пересобирается целиком.

**Кубики и маркер.** `DiceTray` — две кости в середине (красные очко и четвёрка, как на китайских
костях, 3.1.2), во время броска они прыгают и крутятся, а к концу такта ложатся на числа.
После открытия кости остаются на столе: их сумма объясняет разрыв (3.5.7.5), а HUD печатает
`Кубики N+N, бросал <место> · разрыв после K-й стопки`. Свободный стол прячет их через
`DiceTray.SetShown`, не забывая числа. Маркер разрыва — жёлтая планка на сукне с табличной
стороны стены; при продолжении сохранённой партии он не рисуется: стена была разорвана до сохранения.

## Панель действий

Панель — дочерний объект камеры (локальные координаты `(0, −0.128, 0.5)`), поэтому она всегда в кадре
и не зависит от того, как смотрит игрок. Кнопки строятся из `ActionPrompt.FromLegalActions`:

- снос и добор в панель не попадают: снос — клик по кости, добор автоматический;
- окно, где единственный вариант — «Пас», панель не открывает (движок сам его закрывает);
- порядок: Ху → конги → панги → чоу → пас, чоу между собой — по младшему рангу;
- номер кнопки = горячая клавиша `1`..`9`, клик работает через `Physics.RaycastAll` (ближайшая кнопка
  выигрывает, стол и тайлы за панелью не мешают);
- пересборка идёт только при смене `ActionPrompt.Fingerprint`, а не каждый кадр;
- подпись кнопки подгоняется по длине текста (короткая «Hu» крупнее, длинная «Kong East» мельче),
  подсказка берётся из `LegalAction.Description`.

## Сохранение и просмотр партии

Каждый применённый ход идёт через `MahjongGame.ApplyMove(seat, action)`: состояние меняется и ход
попадает в `Replay/SessionLog`. Файл — текст, поэтому его видно в отчёте об ошибке и в диффе:

```
majhong-save v1
session|elapsed=2250|limit=9000
hand|0|12345|East
0|draw|17|-
0|discard|17|-
1|pung|17|23,24
```

Шапка руки нужна, чтобы рука пересобиралась из сида: стена в файл не пишется вовсе. Строка
`session` хранит часы сессии в секундах — по ним игра возвращается на ту же минуту после
продолжения; счёт в файле не хранится, он пересчитывается из переигранных рук. Переменные
окружения:

| Переменная | Что делает |
|---|---|
| `MAHJONG_SAVE` | точный путь файла сохранения (иначе `persistentDataPath/saves/replay-<дата>.mahjong`) |
| `MAHJONG_REPLAY_DIR` | папка сохранений вместо `persistentDataPath/saves` |
| `MAHJONG_REPLAY` | какой файл открыть в просмотре и из какого продолжить (иначе самый свежий сейв) |
| `MAHJONG_RESUME` | `1` — при старте продолжить сохранённую партию вместо новой раздачи |

Просмотр (`V`) ставит руку на паузу и рисует не живое состояние, а состояние курсора — тем же
`RebuildFrom(GameState)`, которым живёт обычная рука, так что отдельного рендерера у просмотра нет.
Клавиши: `←`/`→` — ход, `↑`/`↓` — рука, `Home`/`End` — раздача и конец руки, `V` или `Esc` —
назад за стол ровно туда, где рука остановилась. HUD печатает `Просмотр партии: 1/1 · 7/7`,
`Ход: P4 Сбросить 9b` и остаток стены.

Продолжение партии (`F9` или `MAHJONG_RESUME=1`) идёт через `Replay/SessionRestore`: каждая
сохранённая рука разыгрывается заново по строкам хода (ход, который движок не предложил бы,
останавливает восстановление), завершённые руки начисляются `CompleteHand`, недоигранная остаётся
недоигранной, часы сессии берутся из строки `session`. Если сохранённая рука уже была доиграна,
игра сразу раздаёт следующую. Результат печатается в лог (`[replay] resumed …`) и на шесть секунд
попадает строкой под HUD (`Партия продолжена: рук 4, ходов 213`).

## Размеры, под которые подогнан визуал

`TextMesh` с `fontSize = 64` даёт высоту глифа около пяти `characterSize`, а ширина символа — около
четырёх. Отсюда: подпись тайла — `0.005` (тайл `0.072 × 0.052`), HUD — `0.0016`, подсказка панели —
`0.0018`, подпись кнопки считается как `min(height * 0.11, width * 0.92 / длина / 4.2)`. Эти числа
проверены скриншотом Game view, а не выведены на бумаге: оба раза, когда размеры считались «по логике»,
текст либо не влезал в кнопку, либо не читался.

## Анимации

Анимация живёт целиком в `TileObject` и делится на два слоя, которые не мешают друг другу:

- **переезд** (`SetTarget`) — тайл едет к целевой точке с ease-in/ease-out, небольшим подъёмом на дуге
  и плавным поворотом через `Slerp`; старт можно отложить параметром `extraDelay`;
- **подпрыгивание** (`Pulse`) — смещение по высоте поверх переезда, с необязательной задержкой;
  именно им отмечается объявленный конг (`MahjongGame.AnnounceKongs`), причём задержка берётся из
  `TileObject.LandingDelay`, чтобы тайл прыгнул уже на месте, а не в полёте.

Тайл помнит и «базовую» позицию (результат переезда), и смещение подпрыгивания, а `transform.position`
выставляется как их сумма — поэтому эти две анимации можно включать одновременно.

Темп раздачи задаётся положением кости в кольце стены, а не порядком создания объектов: кость
ждёт `position * DealStagger` (`0.014` с на каждую) от разрыва плюс `TimeUntilDeal` открытия,
замены (с другого конца) стартуют через `ReplacementDelay = 0.85` с. Раньше задержка росла по
порядку создания вьюх и упиралась в `MaxDealDelay = 0.35` с — после перехода на настоящую раздачу
этот потолок стал бессмысленным: волну задаёт расстояние до разрыва.

`IsSettled` истинно только когда тайл приехал и не прыгает; на этом построены PlayMode-проверки
(`TileMotionTests`, `TileAnimationTests`).

## Ограничения прототипа

- Нет звука: анимация движения и конга есть (см. раздел «Анимации»), лицо тайла берётся из атласа
  `Resources/Tiles/tile-atlas.png`, `TextMesh` остаётся fallback.
- Открытие руки показывает лицо кости в момент выкладки, а не прилёта: в стене на секунду видны
  белые кости среди рубашек (починка — первая из визуальных правок в `docs/plan.md`).
- Штрафы судьи (`PenaltyLedger`) в сохранение не попадают: интерфейса судьи в игре нет.
- Ввод на `UnityEngine.Input` (legacy). В проекте `activeInputHandler: 0`, то есть Input Manager
  (Old); при переходе на новый Input System нужно будет переписать ввод.
- Лицо тайла — Quad с текстурой из атласа `Resources/Tiles/tile-atlas.png`; `TextMesh` остаётся
  fallback, если ресурс не найден. Красные пятёрки пока берут обычную ячейку масти.

## Атлас лиц

Атлас `Assets/Resources/Tiles/tile-atlas.png` собирается из SVG-исходников, а не рисуется руками:

```bash
python Tools/Tiles/build_atlas.py     # требуется pip install skia-python
```

Раскладка 9×5 (ячейка 192×256, вся текстура 1728×1280) повторяет `TileObject.AtlasOffset`:
строка 0 сверху — восемь цветов, строка 1 — четыре ветра в столбцах 0–3 и драконы
красный / зелёный / белый в столбцах 4–6, строка 2 — бамбук, строка 3 — доуты, строка 4 — символы.
Альфа-канал сохраняется, фон ячеек прозрачный, цвет тела тайла остаётся за `TileLabel.Face`.

Две вещи проверены на живом рендере, обе ломали картинку незаметно для тестов логики:

- **Нормаль квада.** У `PrimitiveType.Quad` нормаль смотрит вдоль −Z. Поворот `Euler(-90,0,0)` укладывал
  её вниз, и односторонний `Unlit/Transparent` отсекал грань при взгляде сверху — лица просто исчезали.
  Верный поворот — `Euler(90,0,0)`, как у текстовой подписи. Сторожит `TileFaceTests.FaceNormalPointsUp`.
- **Настройки импорта текстуры.** В `.meta` нужны `nPOTScale: 0` (иначе Unity растягивает NPOT-текстуру
  до степени двойки по каждой оси и сетка ячеек перестаёт совпадать с UV), `alphaIsTransparency: 1` и
  `textureCompression: 0` (иначе тонкие штрихи мылятся). Размер текстуры проверяется глазами по логу:
  в проекте он должен читаться как `1728x1280`, а не `2048x1024`.

## Что выяснилось при первом запуске в редакторе

Проверено запуском, а не рассуждением (2026-11-02):

- Unity не знает тип `System.Runtime.CompilerServices.IsExternalInit`, поэтому `record`/`init`
  в ядре правил не собирались (144 ошибки CS0518). Добавлен полифилл
  `Assets/Scripts/Mahjong/Compat/IsExternalInit.cs`; заглушки при headless-сборке его прятали.
- Тайлы парентились прямо к кубу стола с масштабом `(1.35, 0.03, 1.35)` и наследовали его:
  сплющивались по высоте в 45 раз. Теперь тайл — пустой корень с детьми `body` и `label`,
  а на столе есть контейнер `Board` с единичным масштабом.
- Подпись тайла была повёрнута неверно: `LookRotation(up, forward)` плюс разворот на 180° вокруг
  нормали показывали обратную сторону текста, и в скриншотах глифы стояли вверх ногами (`5c` читалось
  как перевёрнутое). Правильный поворот — `Quaternion.Euler(90, 0, 0)`: нормаль текста смотрит вверх,
  верх глифов — в сторону от игрока. Проверено кадром, где три тайла с одним лицом стоят рядом с
  разными поворотами, — на глаз, но однозначно.
- Коллайдер панели перекрывал стол: `Physics.Raycast` брал ближайший объект (куб стола) и клик по
  кнопке не срабатывал. Теперь панель ищет кнопку через `Physics.RaycastAll` и берёт ближайшую к камере.
- После пересборки панели вызывается `Physics.SyncTransforms()`: иначе первый клик по только что
  появившейся кнопке попадал в её прежнее место (в проекте `Physics.autoSyncTransforms = false`).
- Камера не настраивалась, если в сцене уже есть `Main Camera` (а в новой сцене она есть),
  поэтому игра рисовалась на фоне неба и вне кадра. Теперь камера конфигурируется всегда.
- Статус-строка висела над столом и уходила из кадра при наклоне камеры — теперь она дочерняя
  у камеры и читается как HUD.
- `Object.FindObjectOfType` в Unity 6 помечен obsolete — заменён на `FindAnyObjectByType`.
