# Мультиплеер

Сетевой игры в продукте пока нет, но договор сети готов и проверяется headless: серверный стол, проекция
на место, ходы строками, часы сервера и обмен сообщениями по ссылке, которую заменит сокет. Правила игры
при этом не менялись — меняется только то, кто и когда ими управляет.

## 1. Что уже позволяет включить сеть

| Свойство | Где | Почему важно для сети |
|---|---|---|
| Ядро правил без Unity | `Assets/Scripts/Mahjong/Rules` | тот же код крутится на сервере (консоль/headless) и в редакторе |
| Ход описывается одним объектом | `LegalAction`, `GameState.GetLegalActions` | сервер может проверить любой ход клиента: он либо есть в списке, либо это подделка |
| `GameState.Apply(action)` | `Rules/GameState.cs` | одно место, где состояние меняется; всё остальное — проекция |
| Раздача детерминирована по сиду | `GameState.StartHand(dealer, seed, roundWind)` | реплей и догон таблицы без пересылки стены |
| Заявки имеют порядок | `Rules/ClaimPriority.cs` | окно заявок разрешается одинаково на всех столах |
| Время вне движка | `Controls/PlayClock.cs`, `Controls/ClockExpiry.cs` | таймер ведёт сервер и не зависит от часов клиента |
| Штрафы и судья | `Rules/Penalties.cs` | есть чем обслужить спорное решение без переписывания хода |
| Итоги сессии | `Rules/GameSession.cs` | таблица считается на сервере, клиент её только показывает |

## 2. Слои сети

| Файл | Что делает |
|---|---|
| `Net/TileNotation.cs` | Кость текстом: `5c`, `E`, `Fl3`; физическая кость — `5c#17` (`Format`, `TryParse`, `TryParseTile`, `ParseList`) |
| `Net/ActionCodec.cs` | Ход строкой (`discard\|17\|-`), `MoveIntent`, `Resolve` — превращение намерения в `LegalAction` только если движок предлагает именно его |
| `Net/SeatView.cs` | Проекция на место: свои кости, у остальных только число, открытые комбинации, сбросы, стена, чей ход, предложения. `Describe()`/`Read()` — две стороны проводной формы, проекция, записанная и прочитанная, описывает себя так же |
| `Net/AuthoritativeTable.cs` | Единственный владелец `GameState`: проверка хода, отказ без изменений, лог, `Replay` |
| `Net/TableClock.cs` | Часы стола: по окну на место (`SeatClock`), дедлайн — показание **серверных** часов; `Armed`, `Of`, `RunOut`, `Disarm`, `Describe` |
| `Net/WireFrame.cs` | Рамка сообщения `<длина в байтах>\n<payload UTF-8>` и `FrameReader`, который собирает сообщения из произвольно нарезанного потока |
| `Net/TableMessage.cs` | Сообщения провода (`WireKind`, `WireMessage`): кодирование строкой `kind\|поле\|…` с экранированием, фабрики всех сообщений |
| `Net/TableLink.cs` | `ITableLink` (отправить/принять/закрыть) и `LoopbackLink` — две стороны одной связи в процессе, с настоящей рамкой и режимом «по три байта» |
| `Net/TcpTableLink.cs` | TCP-ссылка поверх того же протокола: UTF-8-рамки, чтение доступных данных, закрытие при обрыве |
| `Net/TcpTableHost.cs` | хост стола: принимает TCP-клиентов и подключает их к `TableServer` из игрового цикла |
| `Net/TableServer.cs` | Сервер: места и ссылки, часы, ходы, боты за местами, догон после переподключения, рассылка событий и проекций |
| `Net/TableClient.cs` | Клиент: держит только проекцию, события и остаток окна; ходы уходят `act` с номером запроса, ответ — `accepted` или `rejected` |
| `Net/LocalTable.cs` | Весь стол в одном процессе: сервер + ссылки + клиенты + насос между ними (`Pump`, `Tick`) |
| `Net/InProcessTable.cs` | Прежний стенд без ссылок: боты и человек ходят строками напрямую в `AuthoritativeTable` (им пользуются проверки ядра) |
| `Net/FreeTable.cs` | Общий стол «переставь кости» (песочница `F`) |
| `Diagnostics/RulesSelfTest.Wire.cs` | Группы `wire: …` и `net: …` — сообщения, рамка, проекция, часы сервера, поздний ход, переподключение, рука целиком по ссылкам |

## 3. Архитектура (авторитарный сервер)

```
клиент A ──┐                            ┌── Rules/GameState  (единственный источник истины)
клиент B ──┼── ITableLink ── TableServer ── │  + TableClock (окна 20/10/3 на сервере)
клиент C ──┤                            └── GameSession (раунд, часы, штрафы, таблица)
боты/D   ──┘
```

- Клиент рисует только то, что пришло в проекции, и отправляет намерение: `discard|17|-`, `pung|17|-`.
- Сервер проверяет намерение через `GetLegalActions`, применяет через `Accept` и рассылает события.
- Никакой клиентской логики правил: всё, что клиент «знает», приходит от сервера (иначе два клиента
  разойдутся в спорной руке вроде ограбления конга).
- Боты — такие же места, что и люди: `TableServer.SetBot(seat, bot)` вызывается на сервере, разница
  только в том, что ответ приходит сразу, а не по сети.

## 4. Сообщения

Формат — строка ASCII, разделитель `|`, поле экранируется (`%7C`, `%25`, `%0A`), поэтому причина отказа
может быть целой фразой. Рамка добавляет длину в байтах, так что кириллица в имени игрока ничего не ломает.

| Направление | Сообщение | Поля |
|---|---|---|
| клиент → сервер | `hello` | имя |
| сервер → клиент | `welcome` | место, ветер, дилер, сид, профиль правил, номер события, номер хода |
| сервер → клиент | `view` | место, номер хода, проекция целиком (`SeatView.Describe`) |
| сервер → клиент | `clock` | место, окно (`Arrange`/`Discard`/`Claim`/`-`), сколько миллисекунд осталось (`-` без лимита) |
| сервер → клиент | `event` | номер, вид (`draw`/`discard`/`meld`/`flower`/`turn`/`handEnd`), место, кость, подробность |
| сервер → клиент | `notice` | «P2 ran out of time: pass\|-\|-» — ход сделали часы, а не игрок |
| клиент → сервер | `act` | номер запроса, ход строкой |
| сервер → клиент | `accepted` | номер запроса, номер хода |
| сервер → клиент | `rejected` | номер запроса, причина |
| клиент → сервер | `resume` | сколько событий клиент уже видел |
| сервер → клиент | `resumed` | с какого события догнали, по какое, номер хода |
| сервер → клиент | `refused` | почему места нет («the table is full», «seat 2 is taken») |

Снимок для переподключения — это `resume`: сервер присылает пропущенные `event` и заново проекцию
(`view`) с часами. Полный `GameState` не уходит никогда, поэтому и догонять им нечего.

## 5. Порядок работ

| Шаг | Что делается | Готово, когда | Статус |
|---|---|---|---|
| M0 | `TileNotation`, `ActionCodec`, `SeatView`, `AuthoritativeTable`, `InProcessTable` | четыре бота играют руку только через сообщения, проверки подтверждают: проекция не выдаёт чужие кости, подделанный ход отклонён, лог переигрывается | ✅ 2026-11-05 |
| M1 | Серверные часы: окна 20 / 10 / 3 ведутся на сервере, клиент показывает остаток | просроченный ход не зависит от часов клиента; молчащая заявка становится пасом; ход в сброс, который не сделали, делает за место его бот | ✅ 2026-11-07 (`Net/TableClock`, `Net/TableServer`, группы `net: the table clock …`, `net: a move that comes too late …`) |
| M2 | Транспорт: сообщения, рамка, клиент, переподключение по проекции | обрыв связи не ломает руку: место возвращается на своё место и видит ровно то же, что стол; рука целиком играется по ссылкам, даже если каждая рамка приходит по три байта | 🟡 2026-11-07 — loopback и TCP готовы (`TableMessage`, `WireFrame`, `TableLink`, `TcpTableLink`, `TcpTableHost`, `TableClient`, `LocalTable`); базовый `OnlineLobby` подключён к Unity; полноценный экран лобби и UI-подключение ещё нужны |
| M3 | Турнирный слой: столы, рассадка, судья | 6+ сессий по схеме 3.5.4 | ⬜ |
| M4 | Расчёты между руками: `settle` с выплатами и таблицей сессии | экран результата в сети показывает то же, что в одиночной игре | 🟡 базовый `settled` уже передаёт победителя, очки, способ и платежи; `GameSession`/таблица сессии и UI результата ещё не подключены |

Что закрыто попутно: 4.14 (сохранение сессии) и 4.15 (просмотры) — им нужен был тот же лог ходов
(`Replay/SessionLog`, `Replay/ReplayCursor`, `Replay/SessionRestore`).

## 6. Чего ещё нет

1. **Лобби и WebSocket.** TCP-ссылка и хост для десктопа уже есть (`TcpTableLink`, `TcpTableHost`), а lifecycle-фасад `OnlineLobby` подключён к Unity; остаётся сделать UI лобби. WebSocket для веб-сборки — отдельный транспорт, разговор над ссылкой при этом не меняется.
2. **Лобби.** Строка «Мультиплеер» на приветственном экране серая: нужен экран (хост/подключение, адрес,
   места, готовность) и запуск `TableServer` внутри игры.
3. **Сессия.** Сервер пока ведёт одну руку. Базовый результат руки уже уходит клиентам сообщением
   `settled` с платежами; `GameSession` (раунды, часы партии, штрафы, таблица) и итоговая таблица в сети
   ещё не заведены.
4. **Локальная игра (8.8)** — четыре места за одним столом без сети; `TableServer` для неё уже годится
   (боты садятся за места, люди — за остальные).

## 7. Риски

- **Скорость заявок.** Окно заявки — 3 секунды (3.6.7). Сервер закрывает его по своим часам и не ждёт
  ответа от всех; задержка клиента ничего не откладывает.
- **Спорные руки.** То, что уже решено в `Scoring` (см. `docs/scoring-golden.md`), считается на сервере;
  клиент не должен показывать свой подсчёт даже «для интереса».
- **Подглядывание.** Проекцию держит одно место (`SeatView`), и обходных путей нет: `TableServer` не
  отдаёт `GameState`, `TableClient` его не хранит. Проверки ищут чужие `InstanceId` прямо в тексте
  проекции — и в тексте, который прошёл по ссылке.
- **Часы клиента.** Клиент показывает остаток из сообщения `clock`, а не свой отсчёт: подкрученные часы
  игрока не покупают ему времени.
